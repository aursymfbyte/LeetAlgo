### 效能版

**時間 O(n)**

n 為陣列 `nums` 的長度。

- 先將 n 個數放入集合 `num_set`。集合以雜湊表實作，放入與查詢平均皆為固定步數，記作 O(1)，因此建集合為 O(n)。
- 外層迴圈走訪集合中的每個數。若 `num - 1` 也在集合中，表示該數不是起點，查詢一次即跳過，O(1)。
- 只有起點會進入 `while` 往上計數。注意：雖為兩層迴圈，但每個數只屬於一段連續序列，也只會被該段的起點往上數到一次，因此所有 `while` 合計最多執行 n 次，而非 n × n 次。
- 合計為建集合 O(n) + 外層迴圈 O(n) + 所有 `while` O(n) = **O(n)**。

**空間 O(n)**

- 額外記憶體僅有集合 `num_set`，最多存放 n 個不同的數，為 **O(n)**。

### 可讀性版

C#、Python、C++ 的寫法與效能版相同，時間 **O(n)**、空間 **O(n)**。僅 C 版不同：

**時間：C 版 O(n log n)**

- C 版先以 `qsort` 排序，再由左至右檢查相鄰兩數一次。
- 排序 n 個數約需 n log n 次比較。log n 為 n 反覆除以 2 直到剩 1 所需的次數，n = 10⁵ 時約為 17。後續走訪僅 O(n)，總計為 **O(n log n)**。
- 較效能版慢，因為排序比「放入集合再查詢」多出約 log n 倍的工作。

**空間：C 版 O(log n)**

- 排序直接在原陣列上進行，不另外配置陣列。但 `qsort` 通常以遞迴實作，每層遞迴都會在呼叫堆疊上保存一筆紀錄。呼叫堆疊是系統保存函式返回位置與區域變數的記憶體，遞迴深度約 log n 層，為 **O(log n)**。
- 比效能版省空間，因為不需要集合，代價為時間較慢。
