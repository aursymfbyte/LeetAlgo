### 效能版

**時間 O(n·(k + 26))**

n 為字串的數量（`strs` 的長度），k 為最長字串的長度。

- 外層迴圈逐一處理 n 個字串。
- 每個字串需做兩件事：
  - 將字串中的字母逐一計入長度 26 的計數陣列，最多 k 步。
  - 以這 26 個數字作為雜湊表的鍵進行查詢與存入。計算鍵的雜湊值、比對兩個鍵是否相同，都需走訪 26 格，約 26 步。
- 每個字串花費 O(k + 26)，n 個字串合計為 **O(n·(k + 26))**。
- C 版最後需再走訪 n 個字串，將其放入各自的組別，僅多 O(n)，不影響結論。

**空間 O(n·(k + 26))**

- 雜湊表最多有 n 組（最壞情況為每個字串各自成一組），每組的鍵為 26 個數字，共 n × 26。
- 分組中需存放全部 n 個字串，以每個長度最多 k 估算，共 n × k。
- 兩者相加為 **O(n·(k + 26))**。

### 可讀性版

**時間：C#、Python、C++ 是 O(n·k log k)；C 是 O(n·k log k + k·n log n)**

- 可讀性版不計數字母，而是將每個字串的字母排序後作為鍵。排序長度 k 的字串約需 k log k 步。log k 為 k 反覆除以 2 直到剩 1 所需的次數，k = 100 時約為 7。n 個字串合計為 O(n·k log k)。
- C#、Python、C++ 接著以雜湊表分組，每次查詢或存入需讀取長度 k 的鍵，僅 O(k)，小於排序成本，因此總計為 **O(n·k log k)**。
- C 沒有內建雜湊表，改為將 n 個鍵整體再排序一次，使相同的鍵相鄰。排序 n 個項目約需 n log n 次比較，每次比較兩個字串最多比對 k 個字元，因此多出 k·n log n 一項，C 版為 **O(n·k log k + k·n log n)**。
- 與效能版的差別在於以「排序字串」取代「計數字母」：計數字母僅需 k 步，排序需 k log k 步。

**空間 O(n·k)**

- 四種語言都需為每個字串另存一份排序後的鍵，長度最多 k，共 n 個，為 **O(n·k)**。
- 分組結果最多存放 n 個字串，同樣在 O(n·k) 以內。
