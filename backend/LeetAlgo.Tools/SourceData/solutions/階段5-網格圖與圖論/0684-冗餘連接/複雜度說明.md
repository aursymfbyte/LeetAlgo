n 為邊的數量（`edges` 的長度）。本題的圖為「一棵樹再加一條邊」，因此節點數也恰為 n。

### 效能版

**時間 O(n·α(n))**

- 程式依序處理 n 條邊，每條邊執行兩次 `find`，再最多執行一次合併。合併僅修改一個 `parent` 與一個 `size`，為固定步數。
- 總共為 2n 次 `find`，關鍵在於單次 `find` 的成本。
- `find` 沿 `parent` 往上找到根，樹越高越慢。此處同時使用兩種技巧：
  - 路徑壓縮：找到根後，將路徑上經過的節點直接接到根，下次查詢一步即可到達。
  - 按大小合併：合併時將小集合接到大集合底下，使樹不易變高。
- 兩者並用時，可證明每次 `find` 的均攤時間為 α(n)。均攤指單次操作可能較慢，但將多次操作的總時間平均分攤後，每次的成本為此值。α(n) 為反阿克曼函數，成長極慢，即使 n 大到宇宙原子數，α(n) 也不超過 5，實務上可視為常數。
- 2n 次 × 每次均攤 α(n) = **O(n·α(n))**，實際上近似 O(n)。

**空間 O(n)**

- `parent` 與 `size` 兩個陣列，各 n + 1 格。
- `find` 以遞迴實作，呼叫堆疊（尚未返回的函式呼叫所保存的記錄）深度等於樹高。按大小合併保證樹高不超過 log₂n，因此此部分不超過 O(log n)。
- 合計 **O(n)**。

### 可讀性版

**時間 O(n log n)**

- 同樣為 n 條邊、2n 次 `find`，但只使用路徑壓縮，合併時固定將 `root_a` 接到 `root_b` 底下，不考慮集合大小。
- 缺少按大小合併，樹偶爾會被接得較高；僅靠路徑壓縮時，每次 `find` 的均攤時間為 O(log n)。log n 為 n 連續除以 2 直到變成 1 所需的次數，n = 1000 時約為 10。
- 2n 次 × 每次均攤 O(log n) = **O(n log n)**。
- 與效能版的差別在於少了 `size` 陣列與按大小合併，每次 `find` 由近似常數變為 log n。本題 n 最多 1000，兩版實際執行都很快。

**空間 O(n)**

- 只有 `parent` 陣列，n + 1 格。
- 沒有按大小合併時，樹最壞可能退化成一條長鏈，遞迴 `find` 的呼叫堆疊最深可達 n 層。
- 合計 **O(n)**。
