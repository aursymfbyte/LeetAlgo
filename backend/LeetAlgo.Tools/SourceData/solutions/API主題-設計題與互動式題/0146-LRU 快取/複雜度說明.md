設計題依方法分別計算單次呼叫的成本。capacity 為快取最多可存放的資料筆數。

### get：O(1)

- 先以雜湊表 `nodes` 查詢該 key 是否在快取中。雜湊表查詢平均只需固定步數，與已存放的資料量無關，記為 O(1)。
- 找到節點後，`remove_node` 將其從鏈結串列移除，`add_to_front` 將其接到最前端。雙向鏈結串列的節點直接保存前後鄰居，只需修改四、五個指標，不必從頭走訪尋找，同樣為 O(1)。
- 總計為固定步數，為 **O(1)**。

### put：O(1)

- key 已存在：查詢雜湊表、更新值、移到最前端，與 get 相同為固定步數。
- key 不存在：建立新節點、存入雜湊表、接到最前端。若超過容量，待淘汰的節點即為 `tail.prev`（尾哨兵的前一個節點），可直接取得而不需搜尋；將其移除並從雜湊表刪除，同樣為固定步數。
- 兩種情況皆無迴圈，為 **O(1)**。

若改用一般陣列記錄使用順序，每次將某個 key 移到最前端時，需將中間元素逐一往後挪，最壞為 O(capacity)。採用雙向鏈結串列搭配雜湊表，目的即在使「查找」與「搬移」皆為 O(1)。

### 空間 O(capacity)

- 雜湊表與鏈結串列存放同一批節點，put 超過容量時會立即淘汰一筆，因此任何時刻最多只有 capacity 筆資料（淘汰前的瞬間為 capacity + 1 筆）。
- 另有頭尾兩個哨兵節點，大小固定。
- 空間為 **O(capacity)**。
