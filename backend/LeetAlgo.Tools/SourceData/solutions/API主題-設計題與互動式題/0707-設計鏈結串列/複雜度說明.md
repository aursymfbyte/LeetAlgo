設計題，各方法的耗時取決於目標位置。n 為串列目前的節點數，即程式中的 `size`；index 為本次傳入的位置。

### 每個操作：O(min(index, size - index))

- 鏈結串列無法像陣列直接跳到第 index 個，只能從某一端逐一走過去。
- `node_at` 判斷目標較靠近哪一端：靠近頭則從頭往後走 index 步，靠近尾則從尾往前走 size − index 步。因此最多走兩者中較小的步數，即 min(index, size − index)。
- 找到位置後，插入或刪除只需修改前後鄰居的數個指標；由於有頭尾哨兵，不必特別處理邊界，為 O(1)。
- `get`、`addAtIndex`、`deleteAtIndex` 皆為「找位置 + 固定步數」，為 **O(min(index, size - index))**。
- `addAtHead` 的 index 為 0，`addAtTail` 的 index 為 size，代入後皆走 0 步，因此這兩個方法為 O(1)。
- 最壞情況為 index 恰在正中間，約需 n/2 步，仍與 n 成正比；但較只從頭走（最壞 n 步）少一半。

### 空間 O(n)

- 每個值存於一個節點，串列有 n 個節點，另有頭尾兩個固定的哨兵節點。
- 空間為 **O(n)**。
