互動式題目，只能透過 `mountainArr.get` 讀取陣列，且題目限制最多呼叫 100 次，因此需同時計算時間與 `get` 的呼叫次數。n 為山脈陣列的長度。

### 時間 O(log n)

- 程式共做三次二分搜尋。二分搜尋每比較一次，搜尋範圍減半；n 個位置縮減到剩 1 個需 log₂n 次（log₂n 為 n 連續除以 2 直到變成 1 所需的次數）。
- 第一次找山頂：每一輪呼叫 2 次 `get`（`mid` 與 `mid + 1`），約 log₂n 輪。
- 第二次在山頂左側找 target、第三次在山頂右側找，每一輪各呼叫 1 次 `get`，範圍皆不超過 n，各約 log₂n 輪。
- 三次二分依序執行，並非巢狀，因此總共約 2 × log₂n + log₂n + log₂n = 4 × log₂n 次 `get`，省略常數後為 **O(log n)**。
- 代入題目上限：n 最多 10⁴，log₂(10⁴) 約為 14，最多約 2 × 14 + 14 + 14 = 56 次 `get`，未超過 100 次的限制。

直覺寫法：從頭到尾逐一 `get` 尋找 target，最壞需 n 次，n = 10⁴ 時遠超過 100 次的限制。

### 空間 O(1)

- 僅使用 `left`、`right`、`mid`、`peak`、`value` 等幾個變數，大小固定，與 n 無關。
- 空間為 **O(1)**。
