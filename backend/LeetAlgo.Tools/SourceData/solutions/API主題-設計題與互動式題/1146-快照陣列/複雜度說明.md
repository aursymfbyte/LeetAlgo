設計題依方法分別計算單次呼叫的成本。length 為陣列長度；k 為被查詢那一格目前的修改紀錄筆數。

### set：均攤 O(1)

- `set` 只檢查該格的最後一筆紀錄：若為同一個快照編號則直接覆蓋，否則在尾端新增一筆。
- 覆蓋為 O(1)。附加到陣列尾端通常亦為 O(1)，僅在容量用盡時需搬到更大的空間，該次較慢；但容量按比例放大，搬移次數很少，平均每次仍為固定時間。
- 偶爾有一次成本較高、平均每次仍為固定時間的情形，稱為**均攤 O(1)**。

### snap：O(1)

- 僅將 `current_snap_id` 加一後回傳，不複製任何資料，為 **O(1)**。
- 若每次 snap 都複製整個陣列，每次需 O(length)；此設計避免了這項成本。

### get：O(log k)

- 每一格的紀錄依快照編號由小到大加入，本身已排序，因此可用二分搜尋找出「編號不超過查詢值的最後一筆」。
- 二分搜尋每比較一次，範圍減半；k 筆紀錄縮減到剩 1 筆需 log₂k 次（log₂k 為 k 連續除以 2 直到變成 1 所需的次數），為 **O(log k)**。

### 空間 O(length + set 的呼叫次數)

- 建構時為每一格配置一個空清單，共 length 個，此部分為 O(length)。
- 每次 set 最多新增一筆紀錄（覆蓋時不新增），因此紀錄總數不超過 set 的呼叫次數。
- 合計 **O(length + set 的呼叫次數)**。
