設計題依方法分別計算成本。n 為食物數量，q 為 `changeRating` 的呼叫次數。

堆積（heap）為排成完全二元樹的結構；此處每種料理一個堆，堆頂恆為「評分最高、評分相同時名稱字典序最小」的食物。字典序為從第一個字母開始逐字比較，字母較小者排前。放入一個元素或彈出堆頂只需沿樹的一條路徑調整位置；s 個元素的樹高約為 log₂s 層（log₂s 為 s 連續除以 2 直到變成 1 所需的次數），因此每次為 O(log s)。

### 建構：O(n log n)

- 每道食物在兩個雜湊表各存一筆，平均為固定步數；再放入所屬料理的堆，堆最多 n 個元素，每次 O(log n)。
- 共 n 道食物，為 n × O(log n) = **O(n log n)**。

### changeRating：O(log(n + q))

- 更新雜湊表中的評分為固定步數。
- 不在堆中尋找舊紀錄（在堆中尋找特定元素需逐一檢查，效率低），而是直接推入一筆新紀錄。
- 每次修改評分都使堆多一筆，因此堆大小最多為 n + q，放入一次為 **O(log(n + q))**。

### highestRated：均攤 O(log(n + q))

- 先檢查堆頂，若其記錄的評分與雜湊表中目前的評分不同，即為過期資料，彈出後再檢查下一筆。單看某一次，可能需連續彈出多筆過期資料，耗時較長。
- 每筆紀錄只會被放入堆一次、最多被彈出一次。紀錄總數最多 n + q 筆，因此所有 highestRated 合計的彈出次數不超過 n + q，這些成本分攤到先前的建構與 changeRating 上。
- 平均每次 highestRated 只需固定次數的堆積操作，每次 O(log(n + q))。偶爾有一次成本較高、平均每次仍相近的情形，稱為**均攤**，因此為 **均攤 O(log(n + q))**。

### 空間 O(n + q)

- 兩個雜湊表 `rating_of`、`cuisine_of` 各存 n 筆。
- 所有堆合計：建構時放入 n 筆，每次 changeRating 再多 1 筆，過期資料不一定會被清除，因此最多 n + q 筆。
- 合計 **O(n + q)**。
