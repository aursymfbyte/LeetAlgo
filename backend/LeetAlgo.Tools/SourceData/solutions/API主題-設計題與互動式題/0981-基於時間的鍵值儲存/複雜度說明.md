設計題依方法分別計算單次呼叫的成本。n 為同一個 key 底下已存放的資料筆數。

### set：均攤 O(1)

- set 將時間戳與值分別附加到該 key 的兩個陣列尾端。
- 附加到動態陣列尾端通常為 O(1)。容量用盡時，陣列會配置一塊按固定比例放大的新空間（C# 的 List、C++ 的 vector 為兩倍），並搬移全部舊資料，該次操作成本較高。
- 以兩倍放大為例，存入 n 筆資料的總搬移量約為 n + n/2 + n/4 + … < 2n，平均分攤到 n 次 set，每次僅增加固定成本。
- 偶爾有一次成本較高、平均每次仍為固定時間的情形，稱為**均攤 O(1)**。

### get：O(log n)

- 題目保證 set 的時間戳嚴格遞增，因此每個 key 的時間戳陣列已經有序，可直接使用二分搜尋。
- 二分搜尋每比較一次，搜尋範圍減半；n 筆資料約需 log₂n 次比較，為 **O(log n)**。
- n = 10⁵ 時約需 17 次比較。

### 空間 O(set 的呼叫次數)

- 每次呼叫 set 都會新增一個時間戳與一個值，且資料不會被刪除。
- 總資料量等於 set 的呼叫次數：呼叫 m 次即存放 m 筆，空間為 **O(m)**。
- 此處不寫成 O(n)，因為 n 僅指單一 key 底下的筆數，所有 key 的筆數總和才等於 set 的呼叫次數。
