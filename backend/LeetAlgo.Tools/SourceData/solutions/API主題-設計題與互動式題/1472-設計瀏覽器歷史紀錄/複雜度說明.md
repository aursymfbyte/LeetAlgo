設計題依方法分別計算單次呼叫的成本。n 為 `visit` 的呼叫次數（加上首頁那一筆）。C 版寫法稍有不同，於最後另行說明。

### visit：均攤 O(1)

- `visit` 將 `current` 加一，並在該位置寫入網址：若恰在陣列尾端則新增一筆，否則直接覆蓋舊紀錄，最後更新 `last`。
- 覆蓋為 O(1)。附加到陣列尾端通常亦為 O(1)，僅在容量用盡時需搬到更大的空間，該次較慢；但容量按比例放大，搬移次數很少，平均每次仍為固定時間。
- 偶爾有一次成本較高、平均每次仍為固定時間的情形，稱為**均攤 O(1)**。
- 原本的前進紀錄不需實際刪除，只要將 `last` 設為新的 `current`，舊紀錄即無法再存取，因此不耗費清除時間。

### back、forward：O(1)

- 不逐步往回走，而是直接算出 `current - steps` 或 `current + steps`，再以 `max`、`min` 限制在 0 與 `last` 之間，然後讀取陣列該格。
- 無論 `steps` 多大，都只做固定步數，為 **O(1)**。

### 空間 O(n)

- 陣列 `history` 只增不減，每次 visit 最多使陣列多一格，因此最多 n 格。
- 空間為 **O(n)**。

### C 版

- C 版檔頭標示：每個操作皆為 O(1)，空間 O(n)。
- C 版一開始即依題目上限（最多 5000 次呼叫）配置固定大小的二維字元陣列，visit 直接寫入對應位置，永遠不需擴大或搬移，因此 visit 為 **O(1)**，不需標註「均攤」。
- 複製網址字串需「網址長度」步，但網址最多 20 個字元，視為固定步數。
- back、forward 同上為 **O(1)**，空間同樣為 **O(n)**。
