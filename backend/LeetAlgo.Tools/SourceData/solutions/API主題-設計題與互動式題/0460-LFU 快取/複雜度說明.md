設計題依方法分別計算單次呼叫的成本。capacity 為快取最多可存放的資料筆數。

### get：O(1)

- 先以雜湊表 `key_to_node` 找到節點，平均只需固定步數，記為 O(1)。
- 接著 `increase_freq`：將節點從舊次數的串列移除、次數加一、接到新次數串列的最前端。
  - 雙向鏈結串列移除或插入一個節點只需修改數個指標，為 O(1)。
  - 新次數的串列以查詢一次雜湊表 `freq_to_head` 取得，亦為 O(1)。
  - 舊串列變空時，`min_freq` 只需加一，不必重新尋找最小值：此節點恰好從 min_freq 移到 min_freq + 1，新的最小次數必為 min_freq + 1。
- 全部為固定步數，為 **O(1)**。

### put：O(1)

- key 已存在：更新值後做一次 `increase_freq`，與 get 相同為 O(1)。
- key 不存在且快取已滿：待淘汰的節點即為 `freq_to_head[min_freq].prev`，即最少使用次數那條串列的尾端。由於持續記錄 `min_freq`，不必掃描所有 key 尋找次數最少者，可直接取得。將其移除並從雜湊表刪除，皆為 O(1)。
- 再建立新節點、存入雜湊表、接到次數 1 的串列前端，並將 `min_freq` 設為 1，皆為固定步數。
- 為 **O(1)**。

直覺寫法：每次淘汰時掃描所有 key 尋找使用次數最少者，需 O(capacity)。此寫法以「每種次數一條串列 + 記錄最小次數」使淘汰成為 O(1)。

### 空間 O(capacity)

- 快取中最多有 capacity 個節點，`key_to_node` 最多 capacity 筆。
- `freq_to_head` 只保留仍有節點的串列（變空即刪除），每條串列至少有一個節點，因此串列數不超過 capacity；每條串列另有一個哨兵節點，最多 capacity 個。
- 合計 **O(capacity)**。
