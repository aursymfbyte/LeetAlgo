設計題依方法分別計算單次呼叫的成本。k 為佇列容量，即建構時傳入的 `k`。

### 每個操作：O(1)

- `enQueue`：以 `(head + count) % k` 算出隊尾的下一格，寫入後 `count` 加一。
- `deQueue`：將 `head` 往後移一格（超過尾端則以 % 繞回開頭），`count` 減一。
- `Front`、`Rear`：直接以下標讀取陣列一格；`Rear` 的下標同樣以一次 % 算出。
- `isEmpty`、`isFull`：僅比較 `count` 與 0 或 k。
- 這些操作皆無迴圈，只做幾次加減與取餘數，每個皆為 **O(1)**。

出隊時不將後方元素往前挪，而是讓 `head` 前進、將陣列視為首尾相連的環。若用一般陣列每次出隊都整段往前搬，需 O(k)。

### 空間 O(k)

- 建構時配置一個長度 k 的陣列 `items`，之後不再變大或變小。
- 其餘僅有 `head`、`count`、`capacity` 幾個變數，大小固定。
- 空間為 **O(k)**。
