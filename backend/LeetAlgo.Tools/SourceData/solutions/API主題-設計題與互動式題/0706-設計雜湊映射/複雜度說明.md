設計題依方法分別計算單次呼叫的成本。兩版皆採用「分離鏈結法」：(key, value) 以 `key % 桶數` 決定放入哪個桶，同一桶的資料排成一串，查詢時在該串中逐筆比對 key。因此單次操作的耗時取決於該串的長度。

### 效能版

n 為映射同時存放過的最多 key 數。

**put：期望均攤 O(1)**

- 先算出桶，在桶中尋找此 key：找到則更新 value，找不到則加到尾端。尋找時間與桶中資料筆數成正比。
- 程式保證資料筆數一超過桶數即將桶數加倍，因此筆數恆不超過桶數，平均每個桶不到 1 筆。只要 key 分散夠平均，桶中需比對的筆數平均為固定值，稱為**期望 O(1)**：期望為多種情況平均後的結果，個別桶偶爾較擁擠，平均仍為固定步數。
- 加倍時需將所有資料重新分配到新桶，該次耗時 O(目前筆數)。由於桶數每次加倍，存到 n 筆時所有加倍的總搬移量約為 8 + 16 + 32 + … + n < 2n，平均分攤到先前的 n 次新增，每次僅增加固定成本。偶爾有一次成本較高、平均每次仍為固定時間的情形，稱為**均攤 O(1)**。
- 兩者合併，為 **期望均攤 O(1)**。

**get、remove：期望均攤 O(1)**

- 算出桶後在桶中尋找此 key（remove 找到後移除），不會觸發加倍。
- 桶中平均不到 1 筆，為固定步數，合併寫成 **期望均攤 O(1)**。

**空間 O(n)**

- 每筆 (key, value) 各存一份，最多 n 筆。
- 桶數從 8 開始，筆數超過桶數才加倍，因此桶數不超過 2n（另加初始的 8 個）。remove 後桶數不會縮減，因此以「同時存放過的最多 key 數」計算。
- 合計 **O(n)**。

### 可讀性版

n 為映射大小。

**每個操作：O(n / 1009)**

- 桶數固定為 1009，不會加倍。n 筆資料平均分到 1009 個桶，每個桶平均 n / 1009 筆。
- put、get、remove 皆需在一個桶的鏈結串列中從頭走到目標為止，平均 n / 1009 步，為 **O(n / 1009)**。
- 代入題目上限：最多呼叫 10⁴ 次，n 最多約 10⁴，每個桶平均約 10 筆。

**空間 O(n + 1009)**

- 每筆資料一個節點，共 n 個；桶陣列固定 1009 格，映射為空時也需配置。為 **O(n + 1009)**。

兩版差異：可讀性版桶數固定，存放的資料越多，每串越長、越慢；效能版隨資料筆數加倍桶數，使每串平均長度維持在 1 以下，因此每次操作皆為固定時間。
