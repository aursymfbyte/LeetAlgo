### 時間 O(n · q)

n 為 `nums` 的長度，q 為標成負號的數之總和，即程式中的 `negative_sum = (total - target) / 2`。

- 先以 `sum(nums)` 計算總和，走訪陣列一次，為 O(n)。
- 接著為 0-1 背包求方案數。概念上的「狀態」為「只看前幾個數時，選出總和恰為 c 的方法數」，數有 n 個、c 從 0 到 q，共約 n × q 個狀態。
- 程式外層枚舉 n 個數，內層將 c 從 q 倒序執行到 `num`，最多 q + 1 次，每次只做一次加法，為 O(1)。
- 狀態數 × 每個狀態的工作量 = n × q × O(1) = **O(n · q)**，前面的 O(n) 較小，可忽略。
- 依題目上限 n ≤ 20、總和 ≤ 1000，q 最多 1000，約 2 萬步。暴力解：每個數都嘗試正負兩種，共 2ⁿ 種組合，n = 20 時約 100 萬種。

### 空間 O(q)

- 僅使用一個長度 q + 1 的一維陣列 `f`，為 **O(q)**。
- 不需 n × q 二維表格的原因：處理第 i 個數時，只需要前 i − 1 個數的結果，更早的輪次不再使用，因此同一個陣列逐輪覆蓋。
- 注意：c 必須由大到小更新。如此計算 `f[c]` 時用到的 `f[c - num]` 下標較小、尚未在本輪被修改，仍為上一輪的值，代表尚未使用此數，確保每個數最多只選一次。
