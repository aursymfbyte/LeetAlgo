### 效能版

**時間 O(n log n)**

n 為陣列 `nums` 的長度。

- 外層走訪每個數一次，共 n 次。
- 每個數都在 `tails` 中做一次二分搜尋。`tails` 最長為 n，二分搜尋每比較一次，搜尋範圍減半；n 個元素減半至剩 1 個需 log₂n 次，記作 O(log n)。
- 找到位置後，附加到尾端或取代一個元素皆為 O(1)。
- 總計 n × O(log n) = **O(n log n)**。n = 2500 時，每個數約需比較 12 次，共約 3 萬次。

**空間 O(n)**

- 額外記憶體僅有 `tails`。最壞情況為整個陣列已遞增，每個數都附加到 `tails` 尾端，長度達 n，為 **O(n)**。

### 可讀性版

**時間 O(n²)**

- 動態規劃的「狀態」為 `f[i]`：以 `nums[i]` 結尾的最長遞增子序列長度，共 n 個狀態。
- 每個狀態都需檢查前面所有的 `nums[j]`（j < i），第 i 個狀態需檢查 i 個，工作量並非固定。
- 合計 0 + 1 + 2 + … + (n − 1) = n(n − 1)/2，約 n²/2，為 **O(n²)**。n = 2500 時約 310 萬次比較。
- 與效能版的差別：可讀性版對每個數都掃描前面全部元素；效能版利用 `tails` 已排序，改用二分搜尋，每個數只需 log n 步。

**空間 O(n)**

- 配置長度 n 的陣列 `f`，為 **O(n)**，與效能版相同。
