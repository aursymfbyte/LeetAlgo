### 時間：取決於答案的數量與長度（指數級）

c 為 `candidates` 的長度，`target` 為要湊出的總和。

此題時間沒有簡單的公式，原因如下：

- 排序需 O(c log c)。log c 約為 c 需除以 2 幾次才變成 1，c 最多 30，此部分很小。
- 主要時間在回溯。遞迴過程可畫成一棵遞迴樹：每次 `dfs` 呼叫為一個節點，往下選一個數即往下一層。
  - 每一層至少減去 2（題目保證每個數至少為 2），因此樹最多 `target / 2` 層。
  - 每個節點最多往 c 個方向分岔，最壞情況下節點數隨層數指數成長，約為 c 的 `target / 2` 次方等級。
  - 實際上排序後一旦 `candidates[i] > remaining` 即 `break`，許多分支不會展開；實際規模完全取決於 `candidates` 的數值。例如只有 `[2]`、`target = 40` 時，樹僅為一條 20 層的直線；數字越多、越小，分岔越多。
- 每找到一個答案，需複製一份 `path`，時間為該答案的長度（最多 `target / 2`）。

因此檔頭所述為：時間主要由答案的個數與長度決定，且為指數級。題目保證答案少於 150 個、`target` 最多 40，實際執行很快。

### 空間 O(target)

- `path` 最多存放 `target / 2` 個數，因為每個數至少為 2。
- 遞迴的呼叫堆疊（記錄尚未執行完之函式的記憶體區域）每往下一層即多選一個數，最多 `target / 2` + 1 層。
- 兩者皆為 `target / 2` 等級，省略常數 1/2 後為 **O(target)**。
- 此處計算的是回溯過程的額外空間；回傳的答案為題目要求必須回傳的內容，依慣例不計入。
