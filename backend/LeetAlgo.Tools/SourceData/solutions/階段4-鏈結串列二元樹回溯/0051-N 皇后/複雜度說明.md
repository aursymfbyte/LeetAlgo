### 時間 O(n²·n!)

n 為棋盤邊長，亦為皇后數量（題目限制最多 9）。n! 為 n 的階乘，即 n × (n − 1) × … × 1。

n! 的來源：遞迴過程可畫成一棵遞迴樹，每次 `dfs(row)` 為一個節點，每往下一層即多放一列的皇后。
- 第 0 列的皇后最多有 n 行可選。
- 第 1 列不能與第 0 列同行，最多剩 n − 1 行。
- 第 2 列最多剩 n − 2 行……
- 即使完全不考慮斜線，可能的擺法最多為 n × (n − 1) × … × 1 = n! 種，遞迴樹的節點數亦為 n! 等級。斜線限制會再剪去大量分支，實際數量少很多。

各部分的時間：
- 搜尋：每個節點以 `for` 嘗試 n 行，每次以 `col_used`、`slash_used`、`backslash_used` 三個陣列在 O(1) 內判斷能否放置，因此每個節點 O(n)，合計 O(n·n!)。
- 輸出：每找到一個解，需建立 n 個長度 n 的字串，需 O(n²)。解的數量不超過 n!，此部分最多 O(n²·n!)。
- 兩部分取較大者，為 **O(n²·n!)**。

此為寬鬆上界：n = 8 時 8! = 40320，但實際解僅 92 個，斜線限制使實際步數遠小於此數。

### 空間 O(n)（不計答案）

- `queen_cols`、`col_used` 長度為 n，兩個斜線陣列長度各為 2n − 1。
- 遞迴的呼叫堆疊（記錄尚未執行完之函式的記憶體區域）每往下一層放一列，最多 n + 1 層。
- 全部皆為 n 的倍數，空間為 **O(n)**。
- 不計答案的原因：每個解本身即為 n² 個字元的棋盤，為題目要求必須回傳的內容；計入會掩蓋此寫法實際額外使用的記憶體。
