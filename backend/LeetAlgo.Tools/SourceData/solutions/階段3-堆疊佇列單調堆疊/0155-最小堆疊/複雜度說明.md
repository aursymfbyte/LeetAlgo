設計題依方法分別計算單次呼叫的成本。n 為堆疊中目前的元素個數。

### push：O(1)

- 將 `value` 放入 `values` 頂端，再計算 `min(value, mins 頂端)` 放入 `mins` 頂端。
- 僅一次比較與兩次放入，與堆疊元素個數無關，為 **O(1)**。

### pop：O(1)

- `values` 與 `mins` 各從頂端移除一個。只操作頂端，不需移動其他元素，為 **O(1)**。

### top、getMin：O(1)

- 分別直接讀取 `values` 與 `mins` 的頂端，一步即可取得，皆為 **O(1)**。
- `getMin` 能在 O(1) 完成，是因為 `mins` 的每一層已預先記錄「到該層為止的最小值」，不需每次掃描整個堆疊。若每次 `getMin` 都重新尋找最小值，需 O(n)。

### 空間 O(n)

- `values` 與 `mins` 兩個堆疊高度相同，各存 n 個數，合計 2n，省略固定倍數為 **O(n)**。
- C 版依題目的呼叫次數上限（3 × 10⁴）預先配置陣列，元素數最多即為此值，同樣計為 O(n)。
