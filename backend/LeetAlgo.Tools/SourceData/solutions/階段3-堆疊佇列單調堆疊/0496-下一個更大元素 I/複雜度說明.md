### 時間 O(m + n)

n 為 `nums2` 的長度，m 為 `nums1` 的長度。

- 第一段以單調堆疊掃描 `nums2`，外層迴圈執行 n 次。
  - 內部的 `while` 會彈出堆疊，但每個數只放入堆疊一次、最多彈出一次，整段合計放入 n 次、彈出最多 n 次，為 O(n)。
  - 每次彈出時將答案存入雜湊表 `next_greater_of`，雜湊表寫入平均為固定步數 O(1)。
- 第二段對 `nums1` 的 m 個數各查表一次，每次 O(1)，為 O(m)。
- 兩段相加，總計 **O(m + n)**。

暴力解：對 `nums1` 的每個數，先在 `nums2` 找到其位置，再向右逐一尋找較大的數，最壞需 m × n 次。

### 空間 O(n)（C 版是 O(n + 10⁴)）

- 回傳的 `answer` 有 m 個數，為題目要求的輸出，不計入額外空間。
- C#、Python、C++：
  - 雜湊表最多記錄 n 筆（`nums2` 每個數最多一筆），堆疊最多同時存放 n 個數（例如 `nums2` 由大到小排列時一個都不會彈出），合計 **O(n)**。
- C：
  - 不使用雜湊表，改用大小為 10⁴ + 1 的陣列，直接以數值作為下標記錄答案（題目保證數值範圍為 0 到 10⁴）。
  - 此陣列不論 n 多大都需配置 10⁴ + 1 格，再加上堆疊的 n 格，空間為 **O(n + 10⁴)**。
